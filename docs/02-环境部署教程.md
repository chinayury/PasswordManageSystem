# 02 - 环境部署教程

> 更新日期：2026-11-14
> 适用：密码管理系统 PasswordManageSystem（PDM）

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Linux / Windows / macOS（Docker 部署跨平台一致） |
| Python | ≥ 3.11（源码运行） |
| Docker | ≥ 20.10（Docker 部署，含 compose 插件） |
| 内存 | ≥ 256 MB（轻量 Web 服务） |
| 磁盘 | ≥ 100 MB 源码 + 数据目录（数据库/上传/备份/日志随使用增长） |

## 2. 安装方式

本项目提供两种部署形态，任选其一。

### 2.1 Docker 部署（推荐）

镜像基于 `python:3.11-slim`，数据统一落在 `./data`，备份即打包该目录。

**Linux / macOS：**

```bash
./deploy.sh
# 或手动
docker compose up -d --build
```

**Windows：**

```bat
deploy.bat
```

部署脚本会自动创建 `data` 目录并拉起容器。首次启动时，入口脚本
`docker-entrypoint.sh` 会在 `data/.secrets.env` 自动生成 `SECRET_KEY` 与
`ENCRYPTION_KEY` 并持久化。

访问地址：`http://服务器IP:6084`（宿主端口 6084 → 容器 6082）。
初始管理员：`admin / admin123`，**登录后立即修改口令**。

常用运维命令：

```bash
docker compose logs -f password-manager   # 跟踪日志
docker compose down                       # 停止
docker compose up -d                      # 重启
```

**健康检查**：镜像内置 `HEALTHCHECK`（每 30s 请求容器内 `/healthz` 就绪探针，
含数据库连通性检查）。`docker compose ps` 的 STATUS 列出现 `(healthy)` 即为
就绪；也可手动验证：

```bash
curl -fsS http://127.0.0.1:6084/healthz   # {"status":"ok","version":"..."}
```

### 2.2 源码运行

**安装依赖：**

```bash
pip install -r requirements.txt
```

`wsgi.py` / `run.py` 内置 src 路径注入，装依赖后即可直接运行，无需安装本包。
若需使用模块入口 `python -m app` 或命令行入口 `password-manager`，再安装本包：

```bash
pip install -e .   # 注册 app 包与 password-manager 入口点
```

**生成密钥：**

首次启动会在项目根目录自动生成 `.env`（含 `SECRET_KEY` / `ENCRYPTION_KEY`）。
也可手动生成：

```bash
python -c "import os;from cryptography.fernet import Fernet;print(f'SECRET_KEY={os.urandom(32).hex()}');print(f'ENCRYPTION_KEY={Fernet.generate_key().decode()}')" > .env
```

> **`ENCRYPTION_KEY` 一旦投入使用切勿更换或丢失**，否则已存密码永久无法解密。

**启动：**

```bash
# 方式一：直接运行（仅需 pip install -r requirements.txt，无需安装本包）
python wsgi.py        # 生产入口（waitress，默认 0.0.0.0:8000）
# 或 python run.py   # 开发入口（默认 127.0.0.1:5000）

# 方式二：模块/命令行入口（需先 pip install -e .）
python -m app        # 模块入口（等价于 wsgi.py 的 waitress 模式）
# 或 password-manager  # 命令行入口
```

开发调试可设 `FLASK_DEBUG=1`，但**严禁用于对外生产环境**。

## 3. 目录与文件

```
project-root/
├── src/app/           # 业务源码（标准 src 布局，包目录名 = 发行名 = app）
├── docs/              # 项目文档（01~05 五篇）
├── data/              # 运行期数据（Docker 部署自动创建；源码运行默认在项目根）
│   ├── password_manager.db   # SQLite 数据库
│   ├── uploads/              # 记录附件
│   ├── backups/              # 备份快照
│   ├── logs/                 # 运行日志
│   └── .secrets.env          # 密钥文件（Docker 首启自动生成，务必备份）
├── run.py             # 开发启动入口
├── wsgi.py           # 生产 WSGI 入口（waitress）
├── pyproject.toml    # 构建配置（发行名 app、入口点 password-manager）
├── requirements.txt  # 版本锁定依赖
├── Dockerfile        # 容器镜像构建
├── docker-compose.yml # 容器编排
├── docker-entrypoint.sh # 容器入口（首启生成密钥 + 降权）
├── deploy.sh / deploy.bat # 一键部署脚本
├── .env.example      # 环境变量模板（无真实密钥）
├── .dockerignore     # Docker 构建上下文瘦身
├── CHANGELOG.md      # 变更记录
└── README.md         # 项目简介与快速开始
```

源码运行的可写数据目录默认在项目根（`password_manager.db`、`uploads/`、`backups/`、
`logs/`），均可通过环境变量 `DATABASE_PATH` / `UPLOAD_FOLDER` / `BACKUP_FOLDER` /
`LOG_FOLDER` 重定向到独立数据盘。

## 4. 配置说明

全部配置项见 `.env.example`，逐项用途、获取途径与安全约束见
[04-安全设计说明](04-安全设计说明.md)。核心必填项：

| 配置 | 必填 | 说明 |
|---|---|---|
| `SECRET_KEY` | 是 | 会话签名密钥，缺失拒绝启动 |
| `ENCRYPTION_KEY` | 是 | Fernet 加密密钥，缺失/非法拒绝启动；丢失=数据不可解 |
| `APP_ENV` | 否 | `development` / `production` / `testing`，默认 `production` |
| `HOST` / `PORT` | 否 | 监听地址/端口，非法值告警并回退 |
| `SESSION_COOKIE_SECURE` | 否 | 远程访问必须置 `true`（需 HTTPS） |
| `TRUST_PROXY` | 否 | 仅部署于可信反向代理后置 `true`，取 XFF 末段 |

## 5. 启动方式汇总

| 方式 | 命令 | 适用 |
|---|---|---|
| Docker | `./deploy.sh` / `deploy.bat` | 生产部署（推荐） |
| 生产源码 | `python wsgi.py` | 生产（waitress） |
| 开发源码 | `python run.py` | 本地开发（Flask debug） |

| 命令行入口 | `password-manager` | `pip install -e .` 后可用 |

## 6. 常见问题

**Q：启动报"缺少 SECRET_KEY 或 ENCRYPTION_KEY"？**
A：项目根目录无 `.env`。复制 `.env.example` 为 `.env` 并填入合法密钥，或执行上文
"生成密钥"命令。Docker 部署则确认 `data/.secrets.env` 存在且未丢失。

**Q：端口冲突或想改端口？**
A：改 `.env` 的 `PORT`（源码）或 `docker-compose.yml` 的 `ports` 左半边（宿主端口）。
`PORT`/`THREADS` 非法值不会崩溃，会告警并回退默认。

**Q：Docker 构建拉不到依赖？**
A：`docker-compose.yml` 默认传清华镜像（`PIP_INDEX_URL`）。海外服务器改回
`https://pypi.org/simple`。

**Q：数据如何备份？**
A：Docker 部署打包整个 `data/` 目录即可（含数据库、上传、备份、日志、密钥）。
源码运行备份项目根的 `password_manager.db`、`uploads/`、`backups/` 及 `.env`。
**`ENCRYPTION_KEY`（`.env` 或 `data/.secrets.env`）必须单独备份，丢失将无法解密历史数据。**

**Q：如何初始化/迁移数据库？**
A：应用启动时自动执行幂等增量迁移，无需手动操作。也可手动执行：
`flask --app wsgi init-db`（需先 `pip install -e .` 或源码运行环境）。
