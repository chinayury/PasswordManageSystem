# 01 - 项目介绍与架构

> 版本：V0.1.0 ｜ 日期：2026-11-13
> 适用：密码管理系统 PasswordManageSystem（PDM）

## 1. 项目概述

密码管理系统（PasswordManageSystem / PDM）是一个面向团队的自托管密码管理 Web 系统。
核心能力包括：密码记录的加密存储与按需解密查看、受控共享、两步验证（TOTP）、
API 密钥集成、密码健康审计与全链路操作审计。

本版本为 **v0.1.0 正式稳定版**，是内部 2.x 迭代线归一后的对外唯一基线。系统采用
Flask + SQLite 的轻量技术栈，免单独安装数据库，开箱即用，同时支持源码运行与 Docker
部署两种形态。

> **诚实免责**：本项目是自研的自托管工具，**不可替代经过第三方专业审计的商用口令
> 管理器**。它能显著改善团队口令的存储与协作现状，但不承诺对抗已被攻陷的终端或恶意
> 管理员。能力边界逐条列于 [04-安全设计说明](04-安全设计说明.md)。

## 2. 核心设计原则

1. **安全默认**：密钥缺失拒绝启动，调试模式严禁对外，对外暴露必须置于 HTTPS 之后。
2. **分层解耦**：表现层（routes）→ 业务层（services）→ 数据层（db），横切关注点
   （security / utils）由应用工厂统一挂载，禁止跨层直调。
3. **配置集中**：所有配置集中在 `src/app/config.py`，禁止硬编码散落业务代码；
   配置读取采用"非法值告警 + 回退 + 上下限钳制"的容错机制。
4. **路径自适配**：运行期可写数据目录（数据库/上传/备份/日志）通过 `src/app/paths.py`
   统一解析，兼容源码运行与 PyInstaller 打包运行两种形态。
5. **文档与代码同步**：文档中的路径、模块名、命令均可在真实目录中对应，不一致视为
   未完成。

## 4. 分层原则

- **表现层（`routes/`）**：只负责请求解析、参数校验、调用业务层、渲染响应。禁止直接
  操作数据库或实现业务规则。每个模块导出一个 Flask `Blueprint`，由应用工厂统一注册。
- **业务层（`services/`）**：承载全部业务规则与数据加工。加密、审计、限流等横切逻辑
  在此层或 `security/` 实现，表现层不得重复实现。
- **数据层（`db.py` + `models/` + `schema.sql`）**：SQLite 连接管理、建库与幂等增量
  迁移。业务层通过 `get_db()` 获取连接，禁止在表现层直接执行 SQL。
- **横切（`security/`、`utils/`、`extensions.py`）**：安全响应头、权限、限流、校验、
  时间格式化、扩展实例化，由 `create_app()` 统一装配，各层按需引用。

## 5. 关键技术选型

| 领域 | 选型 | 说明 |
|---|---|---|
| Web 框架 | Flask 3.1.3 | 轻量、生态成熟，应用工厂模式装配 |
| 数据库 | SQLite（WAL + `synchronous=NORMAL`） | 免单独装库，幂等增量迁移 |
| 加密 | cryptography 44.0.1（Fernet） | 记录密码与 TOTP 密钥应用层对称加密 |
| 口令哈希 | bcrypt 5.0.0 | 登录口令与恢复码摘要 |
| 表单/CSRF | Flask-WTF 1.3.0 + WTForms 3.2.2 | 全站 CSRF，API 密钥接口豁免 |
| Excel | openpyxl 3.1.5 + defusedxml 0.7.1 | XML 实体扩张防护，装后自动生效 |
| 两步验证 | pyotp 2.9.0 | TOTP 标准实现 |
| WSGI 服务器 | waitress 3.0.2 | 纯 Python、跨平台、Windows 友好 |
| 配置 | python-dotenv 1.2.3 | 密钥缺失拒绝启动 |
| 打包构建 | setuptools（pyproject.toml） | src 标准布局，包目录名 = 发行名 = `app` |

依赖版本全部锁定于 `requirements.txt` 与 `pyproject.toml`，v0.1.0 全周期零新增第三方包。
